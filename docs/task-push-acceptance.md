# Приёмка push-уведомлений задачника — шаг 7

Чек-лист ТЗ «Push-уведомления по задачнику» (27.10.2026, `workflow-service/push-task.txt`, раздел 6) на настоящих телефонах. Правила событий и получателей — [workflow-service/docs/user-task-push-events.md](../../workflow-service/docs/user-task-push-events.md); обработка в приложении — коммит `c3ed346`.

Проверка на своём Mac в симуляторе iOS (стенд, доставка скриптом, состояния) — [task-push-simulator.md](./task-push-simulator.md).

Автоматические проверки уже пройдены: backend — 339 интеграционных тестов (кто получает, текст, история, повторы, досылка), Mobile — 202 unit-теста (разбор push, переход). Здесь проверяется то, чего тесты не видят: доставка Firebase → APNs/Google → телефон, показ системой и нажатие в каждом состоянии приложения.

## Перед началом

**Сборка и стенд**

- [ ] Backend с коммитами шагов 1–5 (миграция `105-user-task-notifications` применена). Процесс с фоновыми работами запущен (`PROCESS_ROLE=all` или отдельный `jobs`): без него не будет напоминаний, просрочки и досылки.
- [ ] У backend ключ Firebase того же проекта, что `GoogleService-Info.plist` и `google-services.json` приложения (`kcell-a303e`). Без ключа push не уходят, а в истории будет `push_error = 'Push not delivered'`.
- [ ] В Firebase Console загружен APNs-ключ для `com.workflow.kz` — иначе iOS ничего не получит.
- [ ] Свежая нативная сборка из `c3ed346`: `npx expo prebuild --clean` (локальные `ios/` и `android/` устарели). `EXPO_PUBLIC_API_BASE_URL` указывает на стенд из первого пункта.
- [ ] iOS — реальный iPhone со сборкой TestFlight или ad-hoc: в `app.json` у `expo-notifications` режим `production`, симулятор и debug-сборка с development-профилем APNs не проверяют. Нужен Xcode со Swift 6.3 (Expo SDK 57).
- [ ] Android — реальный телефон (эмулятору без Google Play токен не выдаётся), Android 13+ — разрешение на уведомления выдано.

**Учётные записи** (одна компания, все — роль «Клиент»)

| Кто | Где | Зачем |
|---|---|---|
| **А** — автор задач | Web или третье устройство | создаёт задачи и действует |
| **Б** — исполнитель | iPhone **и** Android одновременно | получает push; один пользователь на двух телефонах — по токену на каждом |
| **В** — новый исполнитель | Web | получает передачу; для сценария 03 войти им на телефонах |
| **Р** — ответственный, **Д** — сотрудник | отдел «Продажи» вместе с **Б** | групповые задачи |

Действие одного человека с одного устройства не должно давать push ему же на другом — это и есть проверка «не своё действие».

**Как смотреть, что ушло** (если push не пришёл — сначала сюда):

```sql
SELECT n.created_at, n.event, n.content, n.push_status, n.push_error
FROM notifications n JOIN users u ON u.id = n.user_id
WHERE u.phone = '+7 …' AND n.category = 'tasks'
ORDER BY n.id DESC LIMIT 20;
-- токены телефона: SELECT platform, left(token, 12), last_used FROM fcm_tokens WHERE user_id = …;
```

`push_status`: `sent` — Firebase принял; `failed` + `No active tokens` — у человека нет токена (не вошёл, запрещены уведомления); `failed` + `Push not delivered` — Firebase отказал; `pending` — ждёт отправки (cron досылает раз в минуту).

## B. Состояния приложения

Три push с разным переходом — во всех состояниях на обоих телефонах:

| Состояние | Как получить | 01 → карточка | 06 → комментарий | 13 → «Уведомления» | iOS | Android |
|---|---|---|---|---|---|---|
| Открыто на другом экране | приложение на «Профиле» | | | | | |
| Открыто на той же задаче | карточка задачи на экране | | | | | |
| Свёрнуто | кнопка «Домой» | | | | | |
| Закрыто | смахнуть из списка запущенных | | | | | |
| Не вошёл | «Выйти» в профиле → push → нажать → войти под Б | откроется после входа | | | | |

Что ожидать:

- **Открыто.** Push показывается баннером (iOS — сам, Android — локальным уведомлением приложения), один раз, не два. Нажатие открывает то же, что и из шторки.
- **Закрыто.** Нажатие запускает приложение; после заставки открывается нужный экран, вкладки остаются под ним («Назад» ведёт на них).
- **Не вошёл.** Сообщение «Войдите в аккаунт — задача откроется после входа»; после входа сразу открывается задача. Вход другим пользователем — «Задача удалена или недоступна», без данных задачи.
- **Демо-режим.** Нажатие на push задачи — сообщение «Войдите в аккаунт», переход не выполняется.

## D. Правила ТЗ, раздел 4

| Проверка | Как | iOS | Android |
|---|---|---|---|
| Задача себе не даёт push | Б создаёт задачу себе | | |
| Один push при совпадении оснований | А пишет комментарий в задаче, где Б одновременно исполнитель и упомянут — один push «упомянули» | | |
| Бывший исполнитель не получает дальше | после 03: А меняет срок задачи — Б (бывший) ничего не получает, В получает | | |
| Отдел без ответственного — только назначение | в «Приёмка 02» А меняет приоритет, Д пишет комментарий — Б и Р ничего не получают, А получает комментарий | | |
| Ответственный получает рабочие события | в «Приёмка 02» назначить Р ответственным, А меняет срок — получает только Р | | |
| Без срока нет напоминаний | задача без срока с напоминанием «За 5 мин» — ни напоминания, ни просрочки | | |
| Перенос срока | в 04 до напоминания перенести срок на +10 мин — напоминание приходит к новому сроку, к старому нет | | |
| Выполненная до срока | в 12 завершить задачу до срока — просрочки нет | | |
| Правка и удаление комментария | изменить комментарий, добавив @Б; удалить его — push нет | | |

## E. Доступ и история

- [ ] Push о задаче, к которой доступ потерян (Б был в отделе, его перевели в другой; или задачу удалили), — нажатие: «Задача удалена или недоступна», без кнопки «Повторить» и без прежних данных.
- [ ] Карточка открыта на телефоне, А удаляет задачу — после возвращения в приложение (тихое обновление) карточка показывает «Задача удалена или недоступна».
- [ ] «Уведомления» — все события сценариев с заголовком «Задачник» и текстами раздела A; у удалённой задачи нет «Открыть задачу».
- [ ] Название задачи с «№ 15» в тексте уведомления задачника — не ссылка на заявку 15.
- [ ] Уведомления о заявках ведут на заявки, как раньше.

## Известное, не ошибка

- Значок на иконке iOS — всегда 1, а не число непрочитанных.
- Кнопки напоминания («Выполнено / Через час / …») на Android при показе системой могут не появиться — так было и до этой задачи.
- Push приходит с точностью до минуты: cron напоминаний и досылки работает раз в минуту.
- Если загрузка нескольких файлов оборвалась на середине, о добавленных файлах push не будет.
- В минуту выкладки backend возможен повтор напоминания, отправленного прежним кодом.
