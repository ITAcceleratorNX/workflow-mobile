# Push задачника в симуляторе iOS — ручная проверка

Как проверить push-уведомления задачника на своём Mac: локальный стенд, симулятор iPhone, 13 событий ТЗ. Правила событий — [workflow-service/docs/user-task-push-events.md](../../workflow-service/docs/user-task-push-events.md); приёмка на телефонах — [task-push-acceptance.md](./task-push-acceptance.md).

## 1. Что нужно

Проверено 28.10.2026 на этом Mac (macOS 27.2).

| Что | Сейчас | Что сделать |
|---|---|---|
| **Xcode со Swift 6.3** (Xcode 26.4+ или 27) | Xcode 26.2, Swift 6.2.3 — **сборка не проходит** | Обновить Xcode. Обновление macOS Xcode не обновляет. После обновления открыть Xcode один раз и поставить среду симулятора (Xcode → Settings → Components) |
| Docker Desktop | установлен, после обновления системы был выключен | запустить |
| Ключ Firebase на стенде | нет | файл `workflow-service/serviceAccountKey.json` проекта `kcell-a303e` (путь в `.gitignore`) |
| APNs-ключ в Firebase | не проверить отсюда | Firebase Console → Project settings → Cloud Messaging → Apple app `com.workflow.kz`: загружен **APNs Authentication Key (.p8)**. Сертификат только для production до симулятора не доставит |
| CocoaPods | 1.16.2 | — |

Почему Xcode: Expo SDK 57 (`expo-modules-jsi` 57.1) со Swift 6.2.3 не собирается. Первая ошибка — `RuntimeScheduler.h:53: 'RuntimeScheduler' cannot be annotated with … SWIFT_RETURNS_RETAINED`; если её обойти, следующие — `JavaScriptRuntime.swift: sending 'resultPtr' risks causing data races`. Это требования нового компилятора, а не ошибки проекта.

Без ключа Firebase стенд не примет токен iPhone или Android (`POST /api/fcm/token` отвечает 400 «FCM not available»), и в истории будет `push_error = 'No active tokens'`. Проверить, что ключ из нужного проекта, не открывая его:

```bash
node -p "require('./workflow-service/serviceAccountKey.json').project_id"
```

Должно быть `kcell-a303e`.

## 2. Запуск стенда

1. **База.** В `workflow-service`: `docker compose up -d` — контейнер `my_workflow` (PostgreSQL 15 на `localhost:5432`, его и ждёт `.env`).
2. **Backend.** В `workflow-service`: `PORT=3001 npm run dev` (или конфигурация «workflow-service» в Claude Code). При старте применяется миграция `105-user-task-notifications`. В логе:
   - нет строки `Firebase: no service account key found`;
   - `Cron jobs registered: … user-task-reminders, user-task-push-dispatch …` — без них не будет напоминаний, просрочки и досылки.
3. **Приложение.** В `workflow-mobile` на ветке `feat/task-push-notifications`:
   - `npx expo prebuild --platform ios --clean` — один раз: локальная `ios/` собрана под старый SDK. Папка в `.gitignore`;
   - `npm run ios:local` — сборка и запуск в симуляторе, API `http://localhost:3001/api`.
4. **Вход.** В симуляторе войти получателем (Б) и **разрешить уведомления** в системном запросе.
5. **Токен.** Проверить, что сервер получил токен симулятора:
   ```sql
   SELECT platform, left(token, 12), last_used FROM fcm_tokens WHERE user_id = <id Б>;
   ```
   Строка с `platform = ios` — настоящие push пойдут через FCM. Строки нет — см. «Способ Б» ниже.
6. **Второй участник.** Действия Автора — с веба (`kcell-service-front`, `npx next dev -p 3000`, вход Автором) или вторым симулятором.

Учётные записи: одна компания, роль «Клиент» — **А** автор, **Б** получатель (в симуляторе), **В** новый исполнитель, **Р** и **Д** в одном отделе с **Б**.

## 3. Как доставить push

**Способ А — настоящий push.** Работает, когда в шаге 5 есть токен `ios`, а в Firebase загружен APNs-ключ. Симулятор на Mac с Apple silicon (этот Mac — arm64) получает настоящие push, начиная с iOS 16. Путь — FCM → APNs (sandbox) → симулятор, как на телефоне.

**Способ Б — та же запись, доставленная скриптом.** Когда настоящий push не доходит (нет токена или APNs-ключа) или нужно повторить push без нового действия:

```bash
cd workflow-service
node scripts/simulator-push.mjs --phone "+7 701 000 00 02"   # последняя запись «Задачник» этого пользователя
node scripts/simulator-push.mjs --id 42                      # конкретная запись notifications
node scripts/simulator-push.mjs --phone "+7 …" --dry-run     # только показать, что уйдёт
```

Скрипт берёт из базы стенда сохранённые заголовок, текст и `push_data` и доставляет их через `xcrun simctl push` в том виде, в каком FCM приносит push на iPhone: `aps.alert`, категория кнопок, `time-sensitive`, поля данных и `gcm.message_id`. Проверяется всё, что делает приложение; не проверяется только сеть FCM/APNs.

Почему push не пришёл:

```sql
SELECT n.id, n.created_at, n.event, n.push_status, n.push_error, n.content
FROM notifications n WHERE n.user_id = <id Б> AND n.category = 'tasks' ORDER BY n.id DESC LIMIT 10;
```

`sent` — Firebase принял; `failed` + `No active tokens` — нет токена (способ Б); `failed` + `Push not delivered` — Firebase отказал (APNs-ключ, проект); `pending` — досылка cron в течение минуты.

## 4. Состояния приложения в симуляторе

| Состояние | Как получить |
|---|---|
| Открыто | приложение на экране |
| Свёрнуто | ⌘⇧H (Домой) |
| Закрыто | ⌘⇧H дважды → смахнуть карточку Workflow вверх, или `xcrun simctl terminate booted com.workflow.kz` |
| Не вошёл | Профиль → «Выйти» |
| Push запрещены | приложение «Настройки» в симуляторе → Notifications → Workflow → Allow Notifications выкл. (язык симулятора — английский, пока его не сменить) |

Центр уведомлений — потянуть мышью вниз от верхнего края. Кнопки напоминания — нажать и держать уведомление.

## 5. Чек-лист

Отметка — «✓» или номер замечания. Заголовок всех push — «Задачник». Срок — время Алматы. Если по способу А push не пришёл, сначала посмотреть `push_status` (раздел 3), затем отправить ту же запись способом Б.

### 13 событий

| # | Действие (Автор, с веба) | Б видит текст | Нажатие ведёт | ✓ |
|---|---|---|---|---|
| 01 | создать задачу Б со сроком и приоритетом | `Новая задача «…». Срок: ДД.ММ.ГГГГ ЧЧ:ММ.` — один push | карточка | |
| 02 | создать задачу на отдел Б | `Новая задача для команды «…». Срок: ….` | карточка | |
| 03 | задачу Б передать В; войти в симуляторе под В | `Вам передана задача «…». Срок: ….`; Б и А — ничего | карточка | |
| 04 | задача Б: срок через 7 мин, «За 5 мин» | через ~2 мин `Напоминание о задаче «…». Срок: ….` | карточка; удержание — кнопки «Выполнено / Через час / Завтра / Выкл.» | |
| 05 | комментарий без @ | `Новый комментарий к задаче «…»: {текст}.` | карточка, лента у комментария, подсветка | |
| 06 | комментарий с @Б | `Вас упомянули в задаче «…»: …` — без второго push | карточка у этого комментария | |
| 07 | Б завершает задачу; push — Автору (войти А в симуляторе) | `Задача выполнена «…».` | карточка | |
| 08 | вернуть выполненную задачу в работу | `Задача возвращена в работу «…».` | карточка | |
| 09 | прикрепить два файла за раз | `Новый файл в задаче «…».` — один push | карточка, вложения | |
| 10 | изменить срок, затем убрать | `Изменён срок задачи «…». Новый срок: ….`, затем `Срок задачи «…» убран.` | карточка | |
| 11 | приоритет → «Высокий» | `Изменён приоритет задачи «…». Теперь: Высокий.` | карточка | |
| 12 | задача Б: срок через 3 мин, «В момент срока» | в момент срока один push `Срок задачи истёк «…». Срок: ….`; повторов нет | карточка | |
| 13 | удалить задачу Б | `Задача удалена «…».` | экран «Уведомления» и «Задача удалена», без ошибки | |

### Состояния

Push 01, 06 и 13 — в каждом состоянии:

| | Открыто | Свёрнуто | Закрыто | Не вошёл |
|---|---|---|---|---|
| 01 → карточка | | | | |
| 06 → комментарий | | | | |
| 13 → «Уведомления» | | | | |

- [ ] Открыто: баннер появляется один раз; нажатие ведёт туда же, куда из центра уведомлений.
- [ ] Закрыто: после заставки открывается нужный экран; «Назад» — на вкладки.
- [ ] Не вошёл: «Войдите в аккаунт — задача откроется после входа»; после входа Б задача открывается сама; вход другим пользователем — «Задача удалена или недоступна».
- [ ] Демо-режим: «Войдите в аккаунт», перехода нет.

### Запрет push и история

- [ ] Уведомления выключены в Настройках: push 01 и 05 не показываются, приложение работает, оба события есть в «Уведомлениях», «Открыть задачу» открывает карточку.
- [ ] «Уведомления»: записи задачника с заголовком «Задачник»; у удалённой задачи нет «Открыть задачу»; «№ 15» в названии задачи — не ссылка на заявку.
- [ ] Задача, к которой потерян доступ, и удалённая при открытой карточке — «Задача удалена или недоступна», без «Повторить» и прежних данных.
- [ ] Своё действие Б (задача себе, свой комментарий) push ему не даёт.

## 6. Что в симуляторе не проверить

- Доставку на настоящие устройства и сети операторов, Android — приёмка на телефонах ([task-push-acceptance.md](./task-push-acceptance.md)).
- Число на значке иконки — всегда 1 (известное).
