# Приёмка опросов — шаг 24

Проверка критериев ТЗ опросов (таблица «Критерии приёмки ТЗ → шаги» в [`workflow-service/docs/surveys-plan.md`](../../workflow-service/docs/surveys-plan.md); файла ТЗ в репозиториях нет) на локальном стенде. В первом прогоне (02.11.2026) Backend и Web проверялись только как зависимости приёмки; файлы этих проектов не менялись. Web перепроверен 03.11.2026, после шага 15, — раздел «Повторная проверка Web».

## Среда

- Backend: локальный API на порту `3002`, PostgreSQL 15 в одноразовом Docker-контейнере. База тестовая, без пользовательских данных; все миграции, включая схему опросов, применены.
- Web: временная копия `kcell-service-front` на порту `5173`, направленная на локальный API. Рабочая копия Web не изменялась.
- Mobile: debug-сборка приложения на Android Emulator с API 35. API-адрес эмулятора — `10.0.2.2:3002`.
- Для сценариев созданы отдельные временные учётные записи администратора и клиента, офис и опросы в одноразовой БД. Пароли и токены в этом документе не сохраняются.

Среда: локальный API на порту `3001`, PostgreSQL 15 в одноразовом Docker-контейнере (данные в памяти), рабочая копия `kcell-service-front` (`next dev`, порт `3000`), ветка `feat/questionnaire` со всеми шагами Web. Офисы «Алатау» (22 клиента) и «Нурлы Тау» (1 клиент), временные учётные записи, токены подписаны локальным секретом и в документе не сохраняются. Правила сервера — запросами к API, остальное — в браузере, Desktop (1024 px) и Mobile (375 px).

## Итог и ограничения

Основной пользовательский путь опроса подтверждён живым backend на Web и Android; критерии ТЗ на Web пройдены полностью (повторная проверка 03.11.2026). Открыто: доставка настоящего push (нужна отдельная среда с push credentials; запись в очередь и адрес опроса проверены), ручная проверка состояний ошибок и пустых списков на Android, iOS — не проверялся, для этого проекта используется Android-эмулятор.
