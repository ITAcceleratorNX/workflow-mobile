# Комментарии к задачам в Mobile

Шаги 9–11 плана `workflow-service/docs/task-comments-plan.md`: клиент API и состояние комментариев (шаг 9, разделы ниже до «Ограничений»), лента в карточке задачи ([шаг 10](#шаг-10-лента-в-карточке-задачи)), поле ввода, @ и действия со своими комментариями ([шаг 11](#шаг-11-поле-ввода-упоминания-и-свои-комментарии)). Правила API — в контракте `workflow-service/docs/task-comments-contract.md` и `docs/contracts/task-comments.openapi.yaml`.

## Модули

- `lib/api-errors.ts`, `lib/api.ts` — `request` возвращает прежнее сообщение `error` и в дополнение `status`, `code`, `details`, `retryAfterSeconds`, `aborted`. Прежние экраны читают только `error` и работают как раньше.
- `lib/task-comments/types.ts` — типы контракта.
- `lib/task-comments/errors.ts` — ошибка API в терминах экрана: вид, код, текст.
- `lib/task-comments/api.ts` — запросы, проверка формы ответов, таймаут, отмена.
- `lib/task-comments/feed.ts` — порядок ленты и склейка страниц.
- `lib/task-comments/store.ts` — ленты по задачам, неотправленные сообщения, правка и удаление.
- `lib/task-comments/mention-search.ts` — поиск кандидатов для @.
- `lib/task-comments/request-id.ts` — ключ повтора `client_request_id`, UUID v4.
- `lib/user-task-comments-api.ts`, `stores/task-comments-store.ts` — подключение к `request` и к учётной записи.
- `hooks/use-task-comments.ts` — хук карточки задачи.

Модули в `lib/task-comments` не зависят от React Native: API, сессия и таймеры передаются им снаружи, поэтому их проверяют тесты на Node.

## Ошибки

Экран различает, что случилось, по `failure.kind`:

| Вид | Когда | Что уже сделало состояние | Что показать |
|---|---|---|---|
| `offline` | Нет сети или сервер не ответил за 20 с | Сообщение осталось неотправленным с тем же ключом | «Нет соединения», повтор |
| `unavailable` | 404 `TASK_NOT_FOUND`: задачи нет или она больше не видна | Лента очищена, свои неотправленные остались | «Задача недоступна» |
| `read_only` | 403 `COMMENT_WRITE_FORBIDDEN` | `canComment = false`, лента перечитывается | Лента без поля ввода |
| `forbidden` | 403 `COMMENT_NOT_OWNED`, `MODULE_FORBIDDEN` | После правки или удаления лента перечитана | Сообщение сервера |
| `stale` | 409 `COMMENT_VERSION_CONFLICT`, `COMMENT_DELETED`, 404 `COMMENT_NOT_FOUND`, 400 `INVALID_CURSOR` | Лента перечитана; при `INVALID_CURSOR` — с самых новых | «Комментарий уже изменён», черновик не терять |
| `rejected` | 400 `VALIDATION_ERROR`, 409 `MENTION_NOT_AVAILABLE`, `IDEMPOTENCY_CONFLICT`, 413 | Сообщение осталось неотправленным | Исправить черновик, поля — в `details` (`mentions.2`) |
| `rate_limited` | 429 | — | Повтор через `retryAfterSeconds` |
| `unsupported` | 404 без кода: сервер не знает этого API | — | Скрыть комментарии |
| `server` | 5xx, ответ неожиданной формы | — | «Не удалось», повтор позже |
| `unauthenticated` | 401 | `request` вывел на экран входа, кэш очищен | — |
| `cancelled` | Запрос отменило приложение | — | Ничего |

Текст ошибки — серверный, если сервер прислал код; иначе свой: платформенное «Network request failed» или страница прокси пользователю ничего не скажут.

## Лента

- Открытие и возврат в карточку, возврат приложения из фона и свои изменения перечитывают ленту. Перечитывается всё загруженное — от самых новых до самого старого загруженного, по 100 за запрос. Иначе правки и удаления в уже загруженных страницах не были бы видны.
- История догружается по 30. В памяти — не больше 500 комментариев задачи: виртуализация списка экономит отрисовку, но не память, а обновление перечитывает всё загруженное. Дальше `historyLimited`, история не догружается.
- Если после многих новых комментариев обновление упёрлось в предел раньше, чем дошло до загруженного, более старые загруженные убираются: между ними и прочитанным мог остаться пропуск.
- Страницы склеиваются по ID, из двух версий комментария остаётся более новая: запоздалый ответ не откатит правку или удаление. При равной версии берётся пришедшая копия: права и имя автора меняются без новой версии.
- Порядок — время создания, затем ID. Сервер различает микросекунды, в ответе — миллисекунды, поэтому комментарии одной миллисекунды упорядочены по ID. Курсоры выдаёт сервер, на полноту ленты это не влияет.
- Одно чтение задачи за раз: повторное обновление ждёт идущего, обновление прерывает догрузку истории. Ответ прерванного или заменённого чтения не применяется, даже если сеть его не остановила.
- Ленты задач хранятся отдельно: ответ по одной задаче не попадает в другую. Закрытие карточки отменяет её чтение. Помнятся ленты 5 последних задач; открытая задача, задача с неотправленным сообщением или идущей правкой не забывается и сверх этого.

## Отправка

- Сообщение сразу видно как «отправляется» (`pending`) и получает ключ повтора. Сбой сети оставляет его «не отправленным» с тем же ключом: повтор (`retry`) не создаст копию, даже если первая попытка дошла.
- Повторное нажатие с тем же текстом не создаёт второе сообщение: пока идёт отправка, ждёт её ответа, после сбоя повторяет её с тем же ключом.
- Новый ключ — только после `IDEMPOTENCY_CONFLICT`: прежний занят другим содержимым.
- `discard` убирает неотправленное сообщение и возвращает его текст, чтобы вернуть в поле ввода.
- Закрытие карточки не отменяет отправку: отправленное не теряется.

## Правка и удаление

- По версии, которую видит экран. Ответ заменяет комментарий в ленте, удалённый остаётся на своём месте без текста.
- Изменения одного комментария идут по очереди. Повторное такое же нажатие ждёт идущего запроса. Другое действие — например, удаление во время сохранения правки — начинается после него, с новой версией.
- При `stale` лента перечитывается. Если нужное уже сделано — например, ответ на первую попытку потерялся, — это успех. Иначе конфликт остаётся ошибкой, черновик у экрана.

## Пользователь

Кэш принадлежит вошедшей учётной записи. Выход, вход другого пользователя и демо-режим отменяют все запросы и очищают всё. Ответы прежней сессии не применяются. В демо-режиме комментарии не запрашиваются: его токен сервер не принимает.

## Поиск кандидатов для @

Запрос уходит через 300 мс после последнего изменения. Прежний запрос отменяется, его ответ не применяется. Следующая страница — по курсору того же запроса, без повторов людей. Запрос длиннее 100 символов не отправляется: такого имени нет. Тот же запрос второй раз не отправляется, после ошибки — отправляется.

## Совместимость

- Другие экраны получают от `request` прежние сообщения — тест сверяет их с прежним выражением. Отменённый запрос больше не пишется в лог как ошибка сети; до этого шага отмены никто не использовал.
- Сервер без API комментариев отвечает 404 без кода — это `unsupported`, а не «задача недоступна».
- В TypeScript 6 типы `@types/node` больше не подключаются сами. Тесты исключены из `tsconfig.json` и проверяются отдельным `tsconfig.test.json`, поэтому типы Node не видны коду приложения.

`npm test` проверяет типы модуля и тестов (`tsc -p tsconfig.test.json`), затем запускает тесты `node:test` через `tsx`. Отдельная сборка не нужна. Локально на Node 20.20.2 и 25.8.1 — 60 тестов:

- `lib/__tests__/api-errors.test.ts` — прежние сообщения `request`, код, поля, `Retry-After`;
- `errors.test.ts` — вид каждого кода контракта, старый сервер, сеть, отмена;
- `api.test.ts` — запросы по контракту, только поля контракта в ответе и теле, таймаут, отмена, оборванный ответ;
- `feed.test.ts` — порядок, склейка по версии, перечитывание;
- `request-id.test.ts` — UUID v4, в том числе без `crypto` платформы;
- `store.test.ts` — 27 сценариев: запоздалые ответы, две задачи вперекрёст, закрытие карточки, смена пользователя, повтор с тем же ключом, двойное нажатие, конфликт версии и потерянный ответ, очередь изменений, «только чтение», потеря доступа, предел памяти, кэш задач;
- `mention-search.test.ts` — пауза, запоздалые ответы, страницы, закрытие.

Мутационные проверки роняют набор во всех 36 случаях, среди них: применяется запоздалый ответ; обновление не ждёт идущего; перечитывается одна страница; старая версия затирает новую; повтор с новым ключом; ответы прежнего пользователя; нет очереди изменений; потеря доступа оставляет ленту; «только чтение» оставляет поле ввода; поиск без паузы.

`npx tsc --noEmit` — только три прежние ошибки в `app/register/index.tsx`, `components/mood-check-in-card.tsx`, `components/requests/request-detail-ui.tsx`. ESLint по новым и изменённым файлам — без новых замечаний. `npm run lint` (`expo lint`) проверяет только `app`, `components`, `src` и до этого шага падал на 175 прежних замечаниях.

## Ограничения

- Интерфейс — шаги 10–11: список, поле ввода, выбор упоминаний, диапазоны при правке текста.
- Неотправленные сообщения живут, пока приложение запущено: после его закрытия их нет. Сообщение, которое успело дойти, появится при следующем обновлении.
- Повтор — только по действию пользователя, автоматического нет.
- Хук и ветка отмены в `request` тестами не покрыты: им нужен React Native. Хук проверен в шагах 10–11 в веб-версии, на устройстве — ещё нет.

## Шаг 10: лента в карточке задачи

Карточка задачи (`app/client/tasks/details.tsx`) теперь — один виртуализированный список `TaskCommentsList` вместо `ScrollView`: прежние разделы задачи — его шапка, под ними блок «Комментарии». Сами разделы не менялись: в diff карточки только замена контейнера.

### Что видно

- У комментария — первая буква имени, автор, текст, дата и время в Asia/Almaty («Сегодня, 14:05», «Вчера, 09:30», «24.09.2026, 18:00») и метка «изменено». Упоминания выделены цветом, свои комментарии — мягким акцентным фоном.
- Удалённый комментарий остаётся на своём месте с автором и временем: вместо текста курсивом «Комментарий удалён» в пунктирной рамке. Автор удалённой учётной записи подписан сохранённым именем.
- Первая загрузка — индикатор. Ошибка без загруженной ленты — текст и «Повторить», кроме старого сервера и закрытого модуля: там повтор не поможет. Пустая лента — «Комментариев пока нет».
- Ошибка обновления при загруженной ленте — плашка над лентой с текстом и «Повторить»; лента остаётся.
- Потеря доступа убирает ленту: «Комментарии недоступны: задачи нет или у вас больше нет к ней доступа».
- «Только чтение» — плашка, закреплённая внизу экрана: «Задача доступна вам только для чтения: комментарии можно читать, но не писать». У тех, кто может писать, на этом месте поле ввода (шаг 11).
- Экранный диктор читает комментарий одной строкой: автор, время, «изменено», текст.

### История и обновление

- Открытие карточки показывает последние 30 комментариев. «Показать более ранние» над первым из них догружает ещё по 30: более ранние встают под кнопкой, и то, на что смотрит пользователь, не сдвигается. Поэтому список не использует `maintainVisibleContentPosition`: он закрепил бы прежний первый комментарий, и загруженное ушло бы вверх за экран.
- Ручное обновление — кнопка в заголовке блока. Pull-to-refresh не используется: карточка открывается модальным листом, и на iOS жест вниз у верхнего края закрывает его.
- Сама лента перечитывается при открытии карточки, возврате в неё и возврате приложения из фона (шаг 9).
- Виртуализация: сначала 10 комментариев, дальше пачками по 10, смонтировано окно около 9 экранов — длинная переписка не монтируется целиком.

### Модули

- `components/task-comments/task-comments-list.tsx` — `TaskCommentsList`: список карточки, заголовок блока, догрузка истории, состояния. Плашка «только чтение» в шаге 11 перешла в поле ввода.
- `components/task-comments/comment-item.tsx` — `CommentItem`.
- `lib/task-comments/presentation.ts` — куски текста с упоминаниями по UTF-16 диапазонам, дата и время, первая буква имени, подпись для диктора.

### Проверки шага 10

- `npm test` — 69 тестов, из них 9 новых: упоминания с эмодзи, пересечениями и выходом за текст; «Сегодня», «Вчера» и дата по Asia/Almaty, когда устройство в UTC; первая буква имени; подпись для диктора. Мутационные проверки роняют набор во всех 8 случаях.
- `npx tsc --noEmit` — только три прежние ошибки. ESLint по новым файлам без замечаний, в `details.tsx` те же 11 замечаний, что до шага; `npm run lint` — те же 175 прежних.
- Вручную — веб-версия (React Native Web, ширина 375 px, тёмная и светлая темы) против локального стенда сервиса: одноразовый PostgreSQL 15, миграции, три тестовых пользователя, задача с 72 комментариями и задача без них. Проверено:
  - вид комментариев, упоминаний, «изменено», удалённых, эмодзи, длинного текста с переносами;
  - догрузка истории по 30 без сдвига экрана и исчезновение кнопки в начале переписки;
  - обновление: 72 загруженных — одним запросом; новый комментарий и удаление старого другим пользователем видны после обновления;
  - бывший исполнитель, открывший карточку по ссылке: история, свои прежние комментарии выделены, плашка «только чтение», новые сообщения после обновления;
  - потеря доступа при открытой карточке, ошибка сети с повтором, выход при 401, пустая лента;
  - прежние настройки задачи в шапке списка: переключатели и название сохраняются, фокус поля не теряется.
- Нативная сборка не проверялась: в установленном Xcode 26.2 Swift 6.2.3, а `expo-modules-jsi` 57.1 из Expo SDK 57 требует Swift 6.3. Локальная папка `ios/` к тому же собрана под SDK 54. Эмулятора Android нет.

### Ограничения шага 10

- На iOS и Android не проверены клавиатура, safe area, жесты модального листа и крупный шрифт — это нужно пройти на устройстве или в сборке EAS.
- Бывший участник находит задачу только по ссылке или push-уведомлению: списка задач «только чтение» в Mobile нет (шаг 4 оставил интеграцию в Mobile «при необходимости»). В карточке он видит включённый переключатель «Выполнено», который сервер отклонит, — так карточка вела себя и до шага.
- Веб-версия приложения падала при запуске: `hooks/use-color-scheme.web.ts` импортировал сам себя (с марта 2026). Для проверки шага файл временно подменялся; исправлено отдельным коммитом — файл удалён, веб берёт общий `hooks/use-color-scheme.ts`.

## Шаг 11: поле ввода, упоминания и свои комментарии

Под лентой карточки — поле ввода. В нём пишут новое сообщение и правят свой комментарий.

### Новое сообщение

- После нажатия «Отправить» сообщение сразу появляется в конце ленты как «Отправляется…», поле очищается. Второе нажатие отправлять нечего, поэтому двойное нажатие даёт один запрос. Повтор идёт с тем же ключом (шаг 9).
- Кнопка неактивна, пока нет видимого текста (пробелы, переводы строк и невидимые символы не считаются), если текст длиннее 5000 символов или упоминаний больше 20. Длина считается в кодовых точках, как на сервере: эмодзи — один символ. С 4500 символов под полем виден счётчик «4 500 / 5 000».
- Черновик хранится в состоянии комментариев отдельно для каждой задачи. Закрытие карточки и переход в другую задачу его не теряют, выход или смена пользователя очищают. Хранится, пока приложение запущено.
- После отправки список прокручивается к концу и следует за ним 2 секунды, пока строки дорисовываются и меняют высоту. Перетаскивание и «Показать более ранние» останавливают это.
- Неотправленное сообщение остаётся в конце ленты в красной рамке с причиной: «Не отправлено: …».
  - «Повторить» — только если повтор может помочь: нет сети, сбой сервера, 429, отмена. Идёт с тем же ключом.
  - «Изменить» возвращает текст в поле, если поле пустое; иначе уведомление «Поле ввода занято».
  - «Удалить» — после подтверждения.
  - Если сервер отклонил упоминание, «Повторить» нет. «Изменить» возвращает текст уже без этого упоминания: человека выбирают заново.

### Упоминания

- `@` в начале слова (после пробела, скобки или кавычки) открывает над полем список «Упомянуть участника». Набранное после `@` ищется по ФИО и должности (поиск шага 9: пауза 300 мс, догрузка страниц). Кандидатов даёт только сервер: текущие участники задачи, кроме пишущего. `mail@test` список не открывает. Запрос — одна строка, до 50 символов и до трёх пробелов: дальше это обычный текст.
- Выбор вставляет «@ФИО» и пробел и привязывает упоминание к ID человека. Перед знаком препинания и перед уже стоящим пробелом второй пробел не добавляется. Курсор встаёт после упоминания, фокус остаётся в поле.
- Диапазоны считаются в UTF-16, как в контракте. Правка текста до упоминания сдвигает его, правка после — не трогает. Правка внутри имени делает упоминание обычным текстом: имя больше не совпадает. Если одно изменение объясняется разными местами (рядом одинаковые символы), выбирается вариант, при котором сохраняется больше упоминаний.
- × закрывает список для этого `@`. Если упоминаний уже 20, список сообщает, что больше нельзя. Если поиск ответил «только чтение», карточка перечитывает права.
- В самом поле упоминания цветом не выделяются: `TextInput` не умеет подсвечивать часть текста без своего редактора. В ленте и в неотправленных сообщениях они выделены.

### Свои комментарии

- Долгое нажатие на свой комментарий открывает лист действий. Экранный диктор даёт то же действием «Изменить или удалить». «Изменить» и «Удалить» показываются по правам сервера (`can_edit`, `can_delete`), поэтому у сохранённого читателя их нет. В заголовке блока — подсказка «Удерживайте свой комментарий, чтобы изменить или удалить его».
- Правка идёт в том же поле: над ним заголовок «Редактирование комментария», × отменяет. Недописанное новое сообщение при этом не теряется и возвращается после правки. Сохранение — по версии, которую видит экран.
  - Конфликт версии: лента обновлена, текст правки остаётся в поле с пояснением. Повторное «Сохранить» заменит комментарий.
  - Комментарий уже удалён. Если поле нового сообщения пусто, текст правки переходит туда, без упоминаний удалённых учётных записей, и всплывает уведомление. Иначе появляется пояснение, текст остаётся в поле.
  - Отклонённые упоминания — поле `mentions.N` или его часть (`mentions.N.end`) — убираются из черновика, текст остаётся.
- Удаление — после подтверждения «Удалить комментарий?». На месте комментария остаётся «Комментарий удалён». Пока запрос идёт, в строке времени видно «сохраняется…» или «удаляется…».

### Права отозвали при открытой карточке

- Отправка получила «только чтение»: сообщение остаётся в ленте с «Не отправлено: Задача доступна только для чтения» и одной кнопкой «Удалить». Его текст можно выделить и скопировать. Вместо поля появляется плашка «только чтение».
- Права отозвали, пока в поле был текст (стало известно из обновления или поиска `@`). Вместо поля видно «Не отправлено: задача стала доступна вам только для чтения» или «…больше недоступна», сам текст (его можно выделить) и «Очистить». Черновик молча не пропадает.

### Модули

- `lib/task-comments/composer.ts` — чистые функции поля: сдвиг упоминаний при изменении текста, положение курсора, запрос у `@`, вставка упоминания, проверка перед отправкой, черновики правки и без отклонённых упоминаний.
- `lib/task-comments/store.ts` — черновики новых сообщений по задачам (`drafts`, `setDraft`), очищаются со сменой пользователя.
- `lib/task-comments/mention-search.ts` — `reset()` вместо `dispose()`: поиск сбрасывается при закрытии списка и снова готов к работе.
- `lib/task-comments/presentation.ts` — `failureText`: ошибки полей из `details`, иначе общий текст.
- `hooks/use-task-comments.ts` — `useCommentDraft`, `peekDraft`, `setDraft`; `hooks/use-mention-search.ts` — поиск для списка.
- `components/task-comments/comment-composer.tsx` — поле ввода; `mention-picker.tsx` — список участников; `pending-comment.tsx` — неотправленное сообщение; `comment-actions-sheet.tsx` — лист действий и подтверждения; `comment-item.tsx` — долгое нажатие и «сохраняется…»; `task-comments-list.tsx` связывает их.
- `components/ui/sheet.tsx` — подложка вынесена в отдельный слой. Раньше панель лежала внутри кнопки «Закрыть»: экранный диктор не видел её кнопок, а в вебе получались вложенные `<button>`. Кроме листа действий, `Sheet` нигде не используется.

### Проверки шага 11

- `npm test` — 88 тестов, из них 19 новых:
  - поле ввода — 16: сдвиг и потеря упоминаний, неоднозначное удаление, эмодзи, курсор, запрос у `@`, вставка, проверка перед отправкой, черновики правки и отклонённых упоминаний;
  - черновики в store — 2;
  - `failureText` — 1.
- Мутационные проверки: набор падает в 30 случаях из 31. Выжила одна мутация — «упоминание убирает любое поле с номером»; других полей с номером в контракте комментария нет.
- `npx tsc --noEmit` — только три прежние ошибки. ESLint по новым и изменённым файлам без замечаний; `npm run lint` — те же 175 прежних.
- Вручную — веб-версия (ширина 375 px) против локального стенда сервиса, как в шаге 10. Проверено:
  - `@` предлагает только исполнителя: без самого автора и без сохранённого читателя. Выбор даёт `@Петров Пётр Иванович ` с верными `user_id` и смещениями в базе;
  - двойное нажатие «Отправить» — один запрос и один комментарий; после отправки лента доходит до конца;
  - правка через долгое нажатие и лист действий, метка «изменено»;
  - конфликт версии с «другим устройством»: текст сохранён, повторное «Сохранить» проходит;
  - удаление с подтверждением оставляет «Комментарий удалён» на месте;
  - без сети: «Повторить / Изменить / Удалить»; после восстановления повтор с двойным нажатием — один запрос;
  - упоминание человека, которого переименовали: «Не отправлено: Имя изменилось: выберите человека заново», без «Повторить». «Изменить» возвращает текст без упоминания, фокус в поле;
  - передача задачи другому при открытой карточке: неотправленное с одной кнопкой «Удалить»; недописанный текст с «Очистить» после поиска `@`.

### Ограничения шага 11

- На iOS и Android не проверены: клавиатура в модальном листе карточки, лист действий, safe area, долгое нажатие во время прокрутки, события выделения на Android. Нативная сборка по-прежнему невозможна (см. шаг 10).
- В веб-версии после прыжка к концу длинной ленты с самого верха строки у конца дорисовываются 1–3 секунды (виртуализация React Native Web в сборке разработки). Позиция прокрутки при этом верная. Стоит посмотреть на устройстве.
- Черновики и неотправленные сообщения хранятся в памяти, пока приложение запущено.
- Долгое нажатие не очевидно: о нём говорит только подсказка в заголовке блока.
