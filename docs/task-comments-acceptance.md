# Приёмка комментариев в Mobile — шаг 13б

Критерии готовности ТЗ (`workflow-service/comment.txt`, раздел 13) пройдены в приложении против локального стенда. Backend-проверки тех же критериев — `workflow-service/docs/task-comments-acceptance.md` (шаг 13а). Устройство экрана — [task-comments.md](./task-comments.md).

**Итог.** В задачах одному исполнителю и в командных задачах прежнего формата все критерии выполнены в нативном приложении на Android. Групповые задачи нового формата (выбранные сотрудники, отдел, компания) в Mobile с этим backend не открываются: приложение и backend говорят на разных версиях API назначения. Это не ошибка комментариев, но до решения по двум реализациям групповых задач часть критериев в Mobile для них не выполнима — см. [найденное](#найдено).

## Где проверялось

- **Приложение** — нативная debug-сборка Android (RN 0.86, Expo 57) на эмуляторе Android 15 (API 35). Сборка — из отдельной копии проекта: локальная папка `android/` и `node_modules` репозитория не тронуты. JS загружал Metro. Адрес API задан явно (`EXPO_PUBLIC_API_BASE_URL=http://10.0.2.2:3999/api`), `.env` в копию не попадал, так что рабочий API не вызывался. Эмулятор запускался с `-read-only`: всё установленное в нём исчезло при выключении.
- **Сервис** — настоящий `src/main/index.js` с `PROCESS_ROLE=api` на одноразовой PostgreSQL 15. Все миграции до 091 он применил при старте.
- **Данные** — люди, компании, отделы и группа взаимодействия записаны прямо в БД. Задачи, переписка, правка, удаление, передача и команда созданы через HTTP API, как их делают клиенты:
  - T1 — задача одному исполнителю: Иванова (автор) → Петров, затем передана Сидорову; Петров остался читателем;
  - T2–T4 — задачи нового формата: выбранные сотрудники с ответственной, отдел, компания с ответственным из другого отдела;
  - T5 — командная задача прежнего формата: руководитель Ахметов, участники Петров и Ким;
  - Нурланова — сотрудница соседней компании, связанной группой взаимодействия; Админов — роль `admin-worker`.
- iOS не проверялся: в установленном Xcode 26.2 Swift 6.2.3, а Expo SDK 57 требует Swift 6.3 (как в шагах 10–11).

## Критерии готовности ТЗ

| Критерий | Результат в приложении |
|---|---|
| В открытой задаче есть блок комментариев | Выполнен: блок «Комментарии» под разделами карточки, поле ввода закреплено внизу (T1, T5) |
| Автор и текущие участники пишут | Выполнен: автор и новый исполнитель в T1, участница команды в T5 отправили сообщения с упоминаниями |
| Read-only после передачи читает, но не пишет | Выполнен частично: Петров, открывший T1 по ссылке, видит всю переписку, вместо поля ввода — плашка «только чтение», свои прежние комментарии изменить не может. Найти задачу в списках он не может — списка «только чтение» в Mobile нет |
| Новый получатель видит всю прежнюю переписку | Выполнен: Сидоров видит T1 в списке «Сегодня» и всю переписку до передачи |
| У комментария автор, текст, дата и время | Выполнен: «Сегодня, 11:15» — время Алматы при сервере в UTC |
| Правка только своего, отметка «изменено» | Выполнен: удержание своего комментария открывает «Изменить» и «Удалить», после сохранения — «Сегодня, 11:30 · изменено»; на чужом комментарии удержание ничего не открывает |
| Удаление только своего, на месте «Комментарий удалён» | Выполнен: после подтверждения на месте комментария «Комментарий удалён» с автором и временем, метка «изменено» пропадает |
| @ ищет среди текущих участников | Выполнен: в T1 у автора — только новый исполнитель, у нового исполнителя — только автор; в T5 — руководитель, автор и участник, без самого пишущего |
| Поиск @ по ФИО и должности | Выполнен: должность видна в списке, `@law` нашёл сотрудника с должностью «Lawyer». Кириллицу эмулятор через adb не вводит, поэтому должность для проверки временно была латиницей; поиск по ФИО с кириллицей — на вебе в шаге 11 и на backend в 6б |
| Кто доступен только через группы взаимодействия, не найден через @ | Выполнен: Нурлановой нет ни в одном списке @ |
| Бывшего исполнителя с read-only нельзя упомянуть | Выполнен: Петрова нет в @ у T1 после передачи |
| @ не добавляет человека в задачу и не меняет права | Выполнен: в списке @ только текущие участники, упомянуть другого из интерфейса нельзя; запрос в обход интерфейса отклоняет backend (13а) |
| Admin не получает доступа из-за роли | Выполнен: Админов и Нурланова по ссылке на T1 видят «Задача не найдена», комментариев нет |
| Комментарии не смешиваются с историей действий | Выполнен: у задач прежнего формата истории действий в карточке нет, комментарии — отдельный блок |
| Вложения, реакции и ответы отсутствуют | Выполнен: в поле ввода только текст и @, у комментариев нет реакций и ответов. Раздел «Вложения» карточки относится к самой задаче, как и до шагов |
| Основной интерфейс — Mobile | Выполнен |

Ещё в нативной сборке: двойное нажатие «Отправить» сохранило один комментарий; лента после отправки докручивается до нового сообщения; лист действий и подтверждение удаления (`Sheet`) работают на Android; при входе из приложения лог сервиса записал запрос без пароля (`"password": "[REDACTED]"`).

## Найдено

1. **Групповые задачи нового формата в Mobile не открываются.** Для участника T2–T4 списки пусты: без заголовка `X-Task-Assignment-Version: 2` backend отдаёт только задачи прежнего формата (шаг 3б.1). Карточка по ссылке получает `409 TASK_ASSIGNMENT_VERSION_REQUIRED` «Обновите приложение…». Причина:
   - Mobile этот заголовок не отправляет. Групповые задачи в Mobile (`5c8ce49`, PR #5) написаны под другую реализацию backend — ветку `origin/feat/group-task-assignment` (`ccf598e`, 27.09.2026).
   - Та ветка растёт от нашего шага 2 (`2c0b456`) параллельно шагам 3а–13а. У неё своя миграция `086-user-task-group-assignment.sql` — номер совпадает с нашей `086-user-task-assignments.sql`, а у нас дальше 087–091. Свой `GET /:id/participants`, плюс `/user-tasks/recipients`, `/:id/responsible`, `/:id/history`. Поля ответа — `assignment_type`, `target_*`, `group_permissions`, у нас — `assignment` и `permissions`.
   - Шаги 3а–13а лежат в локальной ветке `demo` и на GitHub не отправлены: `origin/demo` стоит на `2c0b456`.
   - Какую реализацию групповых задач оставить и как свести ветки — решение команды. Пока оно не принято, критерии «текущие участники групповой задачи», «ответственный как участник» и @ в задачах на отдел и компанию проверены только на backend (13а).
2. **Нет списка задач «только чтение».** Бывший исполнитель попадает в задачу только по ссылке или push. Backend отдаёт такой список с шага 4а (`GET /user-tasks?view=read_only`), в Mobile его нет (отмечено ещё в шаге 10).
3. **«Назад» на Android во время правки закрывает карточку, и несохранённая правка пропадает.** Черновик нового сообщения при этом сохраняется. Правка хранится только в поле ввода, это решение шага 11.
4. **В существующем коде:** отладочная сборка на каждом экране показывает `expo-notifications: Custom sound 'default' not found`. Источник — уведомления о сне (`lib/sleep-notifications.ts`, `lib/pushNotifications.ts`, `sound: 'default'`), к комментариям не относится.

## Не проверено

- Пристыкованная экранная клавиатура. У этого AVD включена аппаратная клавиатура, и Gboard показывает только плавающую, которая окно не сжимает. Настройку AVD не меняли. Поле ввода над обычной клавиатурой остаётся проверить на телефоне.
- iOS — см. выше.

## Проверки шага

- Правила, на которых держатся критерии «только свой комментарий», «изменено» и «Комментарий удалён», вынесены из компонентов в `lib/task-comments/presentation.ts` и покрыты тестами:
  - `commentState` — удалён ли и изменён ли;
  - `commentMeta` — строка «время · изменено · сохраняется…»;
  - `ownCommentActions` — что человек может сделать с комментарием.
  - Строка комментария, подпись для экранного диктора и список берут их оттуда: раньше проверки «удалён» и «изменено» были написаны в двух местах.
- `npm test` — 91 тест, из них 3 новых. Мутационные проверки роняют набор во всех 10 случаях, среди них:
  - действия на чужом комментарии и на комментарии удалённой учётной записи без вошедшего пользователя;
  - «изменено» у удалённого;
  - удаление по праву правки.
- `npx tsc --noEmit` — только три прежние ошибки. ESLint по изменённым файлам без замечаний.
